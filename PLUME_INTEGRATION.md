# Plume integration foundation

## Server configuration

Store the Plume values generated by Plume Partner Portal in the NOP server
environment. Do not commit the complete Basic authorization header.

```dotenv
PLUME_AUTHORIZATION_TOKEN_URL=https://external.sso.plume.com/oauth2/REPLACE_ME/v1/token
PLUME_AUTHORIZATION_HEADER=Basic REPLACE_ME
PLUME_SCOPE=partnerId:REPLACE_ME role:partnerIdAdmin
PLUME_API_BASE_URL=
PLUME_TOKEN_REFRESH_GRACE_SECONDS=30
```

`PLUME_API_BASE_URL` remains blank until Plume supplies the operator API base
URL. The M2M **Test Plume Connection** action works without it because token
generation uses `PLUME_AUTHORIZATION_TOKEN_URL`.

## Customer workflow

1. Open a customer profile.
2. Select **Plume Wi-Fi**.
3. Test M2M authentication.
4. Associate the NOP customer/location with its Plume customer ID or location
   ID.
5. Add a `Plume Managed Wi-Fi` service to the customer when it is not yet being
   imported from Platypus.

The Pod and connected-device sections use local cache tables. Live sync is not
enabled until the exact Plume endpoints and response schemas are available.

## Platypus service foundation

`customer_services` includes source-system and rate fields so imported rates
remain traceable to Platypus. `service_rate_mappings` maps a stable Platypus
rate ID to an NOP service type/module. Matching must use the stable rate ID,
not a mutable description.

## Database deployment

SQLite development databases are upgraded automatically by
`app.database.core._sqlite_milestone_45_upgrade`, and new Plume tables are
created by SQLAlchemy metadata.

Production PostgreSQL is intentionally migration-only in this application.
The uploaded source bundle did not contain the Alembic directory, so generate
and review an Alembic revision in the complete deployment repository before
starting this build against PostgreSQL. The revision must:

- add the six source fields to `customer_services`;
- create `service_rate_mappings`;
- create `plume_customer_networks`;
- create `plume_pods`;
- create `plume_client_devices`;
- include the indexes, unique constraints, and foreign keys declared in
  `app/database/customer_models.py`.

Do not use `Base.metadata.create_all()` against production PostgreSQL.
